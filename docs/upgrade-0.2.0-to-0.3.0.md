## 1. 新增字段：`source.source_rate`

```json
{"source": {"asset_id": "clip", "source_in": 60, "source_rate": 2.0}}
```

| 字段 | 含义 |
|---|---|
| `end - start` | **输出帧数**（占多长输出时间） |
| `source_rate` | **每输出 1 帧消耗几个源帧**（缺省 `1.0` = 原速） |
| 消耗的源帧 | `(end - start) × source_rate`，从 `source_in` 起算 |

等价于 ffmpeg 的 `setpts=PTS/2`。`rate=2.0` = 两倍速快放；`rate=0.5` = 半速慢放。

**这正是你们 D5 提的那个诉求**，接口是你们推荐的方案 A。

### 为什么不能靠调 `end` 代替

此前 `end - start` **同时**表示"占多长输出时间"和"要读多少源帧"，两者被绑死。
想快播只能把 `end` 减半 —— **时长对了，内容被截断一半，而且完全静默**
（`issues: []`、`failed: false`、总帧数也对）。`source_rate` 就是把这两件事拆开。

## 2. 音轨也一起变速了（不是只改画面）

只改画面不改声音 = **声画分家**，而且两边时长都对 ⇒ 没有任何一处报错。

所以音轨同步：读 `output_samples × rate` 个采样点，再用 `atempo` 压回来，
**两头一凑输出时长不变**。

- `atempo` 是**时间伸缩、不变调**（不是磁带快进的怪声）；
- `rate < 0.5` 自动拆多级（`atempo` 单级限 `[0.5, 100]`，`0.25 = 0.5 × 0.5`）；
- `rate > 100` **明确报错**。

## 3. ⚠️ 请改掉亮度验收的口径 —— 你们上一轮的结论是错的

### 3.1 你们报的

> 现状：out 0..29 → YAVG `99 → 147`，停在 src≈89 ❌ 内容少一半
> 支持后：out 0..29 → YAVG `100 → 198` 到达 src 120 ✅

**这个"现状/支持后"的对比本身没错**（内容确实少一半 / 确实走到了），
但**两组数字都量错了量纲**。

### 3.2 真相

本仓解码带 `-vf scale=out_color_matrix=bt709`，会把源的
**Y（tv 范围 16..235）** 转成 **R（全范围 0..255）**。两者差一个**固定换算**：

```
R = (Y − 16) × 255 / 219
```

`(100 − 16) × 255 / 219 = 97.8` ⇒ 出片确实是 **97**。

所以"`100` 变成 `97`"**不是漂移**，是**少除了这一步**。
`147` 是同一回事：它对应源 Y ≈ 148，不是 147。

### 3.3 对齐口径后：**30/30 帧精确**

用你们给的素材与参数（`source_in=60`、`rate=2.0`、out 30 帧）：

```
out[i] == ( src[60 + 2i].Y − 16 ) × 255 / 219      —— 30/30 帧吻合

出片         97  101 104 109 112 116 …  197 202 206 209
源第60+2i帧 100  103 106 110 113 116 …  186 190 193 196
```

**出片第 i 帧就是源第 `60+2i` 帧，一帧不差。**
（`rate=1.0` 同样精确。）

### 3.4 一个容易骗过人的地方

`R − Y` 随亮度**线性增大**（低处 −3、高处 +13），**看着完全像"越走越偏"的时间漂移**。

但**真的帧漂移是阶梯**（隔一段跳一格），**不是线性**。

> **规矩：误差随"被测量的值"线性增长时，先怀疑量纲，再怀疑时间。**

### 3.5 建议你们改成

```js
// 二选一
const expect = (srcY - 16) * 255 / 219;      // 换算后再比
// 或者干脆比结构：帧数、相对变化率、首末落点 —— 不比绝对亮度
```

## 4. 你要改什么

### 4.1 必须做

| 项 | 说明 |
|---|---|
| 替换产物 | 换成 `dhampir-0.3.0-win32-x64.zip`（结构与 0.2.0 **完全一致**） |
| **改亮度验收口径** | 见 §3。**这是唯一"必须动脑子"的地方** |

### 4.2 不用做

| 项 | 为什么 |
|---|---|
| 改契约校验 | `project_schema = 1` **没动** |
| 改 wasm 导出调用 | `host_api = 6` **没动** |
| 改产物路径/文件名解析 | 目录结构没动（`preview/` + `bin/` + `VERSION`） |
| 重新调字幕像素 | 0.2.0 的 libass 结果没动 |
| 给老工程加字段 | `source_rate` 缺省 `1.0`，**不写就是原速** |

### 4.3 想用变速时才做

在 `source` 里加 `source_rate` 即可。注意两条**会报错**的边界：

| 值 | 行为 |
|---|---|
| `rate <= 0` / `NaN` / `inf` | **`probe` 报 `source_rate_invalid`** |
| `rate > 100` | **报错** |
| `0 < rate < 0.5` | ✅ 允许，自动拆多级 `atempo` |

**故意不兜底成 1.0**：`0` 是"定格"、负数是"倒放"，都不是"快慢"能表达的语义。
悄悄当原速会让你"设了但没生效"而没有任何提示。
