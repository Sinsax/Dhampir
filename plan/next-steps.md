## 四、接手时该知道的坑

1. **改了 Rust 一定要重建 wasm pkg**，否则 check-web-invariants 变红，
   而报出来的错与真实原因毫无关系。命令（工作目录 crates/dhampir-wasm）：

       wasm-pack build --dev --target web --out-dir www/pkg

2. **不许引第三方 crate**。文本栅格化走 ffmpeg，不引字体库。
3. **Windows 上跑 cargo test --workspace 会打印一条 linker stdout 的 warning**，
   那是 link.exe 的进度行，不是代码告警；口径是 cargo check --all-targets 干净。
4. **ffmpeg drawtext 已经探过路**（本轮实核，命令可用；现落在 text_raster.rs，这段是它的口径）：

   透明底用 lavfi 的 color 源，颜色写作 black 加 @0.0，尺寸写作 宽x高，再 format 成 rgba；
   输出走 rawvideo 加 pix_fmt rgba 到 stdout，直接拿到紧排的 RGBA ——
   **于是不需要 PNG 解码器**。
   字体路径里的冒号必须转义（一个反斜杠加冒号），
   文本走 textfile 参数而不是塞进 filter（用户内容里的冒号与单引号会毁掉整条命令）。
   实测 320x64 输出 81920 字节，与 宽 乘 高 乘 4 相符；退出码 0。

5. **改文件一律 LF、无 BOM**，check-text-hygiene 盯着。
6. **只勾真做完的**；台账里标 done 必须给出存在的证据文件（守卫会查）。
7. **`check-sequential-decode.mjs` 扫的是整份文件文本**（注释与 `#[cfg(test)]` 里的测试也算）。
   它要求：文件里出现 `rawvideo` 就得同时出现 `out_color_matrix`（栅格化那条路没有 YUV 那一步，
   所以靠一行注释满足它，见 text_raster.rs 顶部，**别删**），
   并且**不许出现那两个逐帧 seek 选项的带引号字面量** —— 想断言「参数里没有它」，
   就得在测试里把名字拼出来（`format!("-{}", "ss")`），写死会让守卫自己变红，而假红比没守卫更坏。
8. **`rustfmt` 会顺着 `mod` 递归格式化整个模块树**。对本仓的既有文件来说，它的风格与当年不完全一致
   （例如 `ctx.device.create_command_encoder(...)` 会被拆成三行），所以**只对自己改的文件跑**，
   跑完用 `git diff` 确认没有把无关行卷进来。`cargo fmt --check` 不是本仓的判据。
9. **有派生物就得重生成**：改 `dhampir-timeline` 的公共类型之后要跑 `node scripts/timeline-contract.mjs --write`。
   `870e1ec` 漏了这一步，schemas 一直停在旧版直到 T2.4 才补上 —— 这类漂移不会自己变红，
   除非有人正好跑那个脚本。
10. **`check-overlay-plumbing.mjs` 是「通用律 + 两个钉死的宿主」**：以后**新写的**宿主只要
   既渲染帧又读时间线，就会被自动要求评估 overlay —— 这是有意的（漏接的宿主看起来完全正常）。
   它的窗口是**按行数**的（评估后 8 行内要有画、拷位图后 20 行内要声明 alpha）：
   把这两个调用拆远会让它假红，那时改窗口而不是删判据。
   它**只判接线**，不判墨迹；墨迹在 T2.4 / T2.5 的判定通道里。
11. **`docs/host-api.md` 的名单是手写的**：改 wasm 导出（新增/删除/改名 `dhampir_*`）之后要
   手工同步文末那份名单（**当前 26 行** —— 这里原写「23 行」，是 T2 时代的数，T3 的弹幕位图 +1、
   T4 的 undo/redo +2 之后没人跟着改），`--write` 只补掉过时的**版本行**与调用面清单表，
   名单一个字节都不碰。**别把行数写死**，以 `api-surface.mjs` 打印的「列了 N 个导出」为准。
   漏同步的失败形状是 `api-surface` 正跑红并逐条列出缺了谁 —— 这一步是故意的。
12. **反向验证脚本整份回写文件会刷新 mtime**：内容与还原前逐字节一致（脚本自己比 SHA256），
   但 `check-web-invariants` 只看 mtime，于是报「wasm pkg 比它的源码旧」。**重建一次 pkg 即转绿**，
   别去改守卫 —— 它挡的正是「改了 Rust 没重建」这件真事。
13. **变异锚点必须够长，否则「变异无效」会伪装成「守卫漏判」**：同一个函数在同一个文件里有两份
   同形片段时（`resolve_font(args)` 在 `cmd_frame` 与 `cmd_render` 各一份），短锚点会命中错的那处，
   守卫盯的那条路根本没被改动。反向脚本要**显式报出「没被抓住（或变异无效）」并失败退出** ——
   否则人会拿假信号去改守卫（T2.7 的 M4 就是这么栽过一次）。
14. **判定通道的「一致」两个字本身可能是空的，所以 T3.4 加了两条非空白判据**：工程里**有**弹幕轨时，
   五个帧里「一条都没见到」或「一帧都没丢过条」都判红。没有这两条的话，`lanes: 5`（一条都不丢）
   与 `lanes: 0`（一条都排不出）这两种工程会**全绿通过** —— 两端当然一致，只是什么也没验到。
   加判据时先各留一个真反例（`target/t3/reverse/`），别只看正例绿。
15. **PowerShell 的 `*>` 重定向写出来的是 UTF-16**：判定通道的原始输出用它存下来之后，
   `Get-Content` 要带 `-Encoding Unicode` 读，`Select-String` 才不会一行都匹不上
   （现象是"明明红了，日志里却只有标题"）。要 UTF-8 就把内容交给脚本里的
   `fs.writeFileSync` 写，别让 PowerShell 的重定向经手。
16. **改版本号要全文搜一遍**：`api-surface.mjs --write` 只自动改**它抄的那一行**
   （`docs/host-api.md` 的版本行）与调用面清单表；文末的导出名单与**人写的正文**一个字节都不碰 ——
   T4 就在正文里残留过一句「现在等于 3」（守卫不会红，得自己搜）。
17. **时间线拖拽的判定不许预测 Rust 会不会接受**：T4.3 第一次真机红是**场景挑错**
   （固定拖一条已排满的轨道 → `layer_overlap`），不是代码错。做法是：场景按「边界旁边一帧」的
   一般形态**现取**、靠状态栏那句话变没变判引擎收没收、被拒就换下一个、一次都没拖成就如实报失败。
   **预判会把「规则只有一份」这句话咬断。**
18. **wasm 侧没有文件系统**：`crates/dhampir-wasm` 的测试里读 fixture 只能
   `include_str!(concat!(env!("CARGO_MANIFEST_DIR"), "/../../fixtures/..."))` 编进去；
   而且那个文件的 `#[wasm_bindgen_test]` **属性条数**要与 `scripts/run-wasm-tests.mjs` 对账
   （写成 `#[test]` 不会被数到，跑了也白跑）。
19. **在 WorkBuddy 的 agent 会话里跑守卫，先看这一条**：那个会话里**别人给子进程开 stdin 管道**
   会失败 —— node 侧是 `spawnSync` 报 `EBUSY`（`status` 是 `null`，守卫把它显示成 `exit=-1`），
   Rust 侧是 CLI 出片起不了编码器（`所有的管道范例都在使用中。 (os error 231)`，即
   `ERROR_PIPE_BUSY`）。于是 `check-cli` / `check-local-backend` / `check-dual-end` 这三个
   必然**假红**，CLI 的 `render` 必然起不来。
   **别去改守卫、也别去改出片代码** —— 判据、绕过方法与本次复核的原始结论见第五节。
