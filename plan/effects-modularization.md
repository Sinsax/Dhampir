## 零、这一轮要解决什么

当前特效/转场/混合模式的**可扩展性三者各不相同**，而这是加新功能前必须先摆平的东西：

| 能力 | 数据面 | 渲染面 | 加一个新的代价 |
|---|---|---|---|
| **Effect** | ✅ `kind: String` + 注册表 | ❌ **硬编码**在 `render/timeline.rs` | 改 core 渲染代码 |
| **BlendMode** | ⚠️ Rust enum | ✅ 已实现 4 个 | 改 enum + 两端 |
| **TransitionKind** | ❌ Rust enum + schema enum | ❌ 只有 1 种 | **升 SCHEMA_VERSION** |

一句话：**数据可扩展、渲染不可扩展**。

### 三条不可退让的既有约束

这一轮**不许**破坏它们（它们都有守卫或测试盯着）：

1. **两端一致**：同一份工程在 wasm 与 native 下结构一致、可比。
2. **逐字节稳定**：序列化必须逐字节可复现（`BTreeMap` 不是 `HashMap`；撤销/重做逐字节往返有测试）。
3. **不静默降级**：做不到的事要**报错**，不许按 normal 画过去
   （`BlendMode::is_implemented` + `unimplemented_blends` 就是这条的产物）。

## 一、先摆正一处事实（我上一轮说错了）

我此前把「schema 只生成 v1」列为缺口，**这个判断是错的**。
`examples/emit_schema.rs` 已经**能出三种形态**：

```
--doc          ProjectDoc   （写入形态，工程文件）
--timeline     TimelineV2   （渲染契约本体）
--project-v1   Project      （裸契约 v1，兼容形态）
--all          三份打成一个包
```

缺的只是 **`timeline-contract.mjs` 只调了默认的 `--project-v1`**，于是
`schema/timeline-v1.*` 描述的是**已冻结的 v1 兼容形态**，而不是当前运行时认的 v3 契约。

**修正后的缺口**：不是"生成器不行"，是"**派生物没跟上运行时**"。
这反而更好办——不用写生成器，只需要**多生成两份 + 改文件名 + 加守卫**。

## 三、分段计划

### S1 · 派生物跟上运行时（纯文档面，零风险）

**做什么**：让 `schema/` 反映**实际在用的**三种形态，而不是只反映 v1。

- `timeline-contract.mjs` 增加生成 `--doc` 与 `--timeline` 两份；
- 产出 `schema/doc-v1.schema.json` + `.d.ts`、`schema/timeline-v3.schema.json` + `.d.ts`；
- **`timeline-v1.*` 原样保留**（它描述 v1 兼容形态，仍被迁移梯子引用，不能删）；
- 守卫改为**三份都比对**（`--write` 后逐字节复现）。

**为什么排第一**：后面每一段都要靠契约验证"两端结构一致"。**没有准确的 v3 契约，改特效就无法验证。**

**验收**：`node scripts/timeline-contract.mjs` 绿；三份派生物都能 `--write` 后逐字节复现；
故意改一个 Rust 字段 → 三份里**对应的那份**变红（反向用例）。

**风险**：低。不动 Rust 类型，只动脚本与生成物。

---

### S2 · 特效注册表长齐（纯 core，不动 schema）

**做什么**：给 `EffectSpec` 补上两个字段，把"只活在注释里"的约束变成**可校验的数据**。

```rust
pub struct EffectSpec {
    pub kind: &'static str,
    pub params: &'static [(&'static str, f32, f32)],
    pub space: EffectSpace,        // 新增
    pub pipeline: EffectPipeline,  // 新增
}
```

- `space: Source | Document` —— 这条**必须**显式声明。现在"每层模糊跑源空间、
  调整图层跑文档空间"只写在 `render/timeline.rs:271-274` 的注释里，
  而它直接决定**要不要按目标尺寸缩放半径**。搞错 = 两端静默分叉。
- `pipeline` —— 渲染怎么走（先只登记 `SeparableBlur`，为后续扩展留位）。

**验收**：
1. 现有 547 条测试**一条不改**仍全绿；
2. 真机出片与改动前**逐字节相同**（钉住"这只是重构"）；
3. 新增一条测试：`space == Document` 的特效必须走缩放路径（反向用例：声明成 Source 就会算出不同半径）。

**风险**：低。纯 core 内部。

---

### S3 · 渲染派发改成查表（纯 core，不动 schema）

**做什么**：把 `Step::Adjust` 从"就是模糊"改成"按注册表派发"。

- `render/timeline.rs` 里那个无条件 `self.blur.blur_separable(...)` 分支，
  改成按 `spec_of(kind).pipeline` 查表；
- `blur_radius()` 不再是写死查 `"gaussian_blur"` 的函数，而是 pipeline 参数的一部分。

**做完之后的目标**：**加第 2 个特效不需要动 `render/timeline.rs`**——只需登记项 + 一个 pipeline 实现。

**验收**：
1. 同 S2 第 1、2 条（测试不改、出片逐字节相同）；
2. 新增一条**结构性断言**：往注册表加一个假特效（测试内），渲染计划能识别它并派发，
   而不是掉进模糊分支。

**风险**：中。动的是渲染主路径。**用"出片逐字节相同"兜底**。

---

### S4 · 守卫：登记表与实现必须对得上

**新增 `scripts/check-effect-registry.mjs`**（第 19 个守卫）。

判据（双向）：
- 登记表里的每个 `kind` **必须有**对应的 pipeline 实现；
- 反向：实现了 pipeline 却没登记 → 也红（"实现了没登记"会表现为用户填了 kind 却被判 `unknown_effect`）。

带 `--self-test` 与反向用例（临时植入一个"登记了但没实现"的 kind，确认真的红）。

**为什么必须有**：这正是这个仓库的纪律——「**守卫若不会红，就不是守卫**」。
而且它防的正是 S2/S3 之后最可能出现的失效：**加了登记项忘了实现**。

**风险**：低。

---

### S5 · 转场去枚举化（**要升 SCHEMA_VERSION**，放最后）

**做什么**：`TransitionKind` 从 Rust enum 改成与 `Effect` 同形的 `kind: String` + 注册表。

**为什么放最后**：
- 它是**破坏性改动**，要走迁移梯子（`v3 → v4`）、碰 serde、schema 生成器、TS 类型；
- 最好等 S2/S3 把形状定稳，**一次性**改，而不是改两次。

**验收**：
1. 迁移有测试：v3 工程读进来 → v4，且**渲染结果与 v3 逐字节相同**（沿用 `migrate_v1_to_v2` 的既有判据）；
2. 反向：拒绝未知版本（既有行为不许放宽）；
3. 加第 2 个转场**只需登记**，不动 schema。

**风险**：中高。**如果不急，这一段可以只写计划不实施。**

---

### S6 · （可选）补特效种类

**只有 S2+S3 做完之后才做**，否则每加一个都要复制一遍硬编码。

第一批候选（按两端可确定性排序，模糊/色彩矩阵这类**没有随机性**的优先）：
亮度/对比度/饱和度、色温、裁剪、`fade_in/out`。

**验收**：每个特效两端结构一致（走既有 `--verdict` 通道），且**无该特效的工程逐字节不变**。

## 四、顺序与依赖

```
S1（派生物）──> S2（EffectSpec）──> S3（派发）──> S4（守卫）──> S6（新特效）
                                        │
                                        └──> S5（转场去枚举，独立，可延后）
```

**为什么 S1 在最前**：它是后面所有验证的**判据基础**。
**为什么 S4 在 S3 之后而不是之前**：接线之前写守卫，它盯不到任何东西，写出来就是一个恒真的守卫
—— 而**恒真的守卫比没有守卫更坏**（这是 T2.6 记下的教训，原文在 `plan/next-steps.md`）。

## 五、明确不做（本轮）

| 不做 | 为什么 |
|---|---|
| 可上传的自定义 shader | 契约里写死了理由：**等于把两端一致性交给用户** |
| 需要读目标像素的混合模式（后 5 个） | 要走 ping-pong，是另一个数量级的改动（`compose.rs` 已写明） |
| 加 `image` 轨 / 音频特效 | 本轮目标是**摆平既有三条的扩展性**，不是加新类别 |
| 动 v1 兼容形态 | 迁移梯子依赖它；`schema/timeline-v1.*` 原样保留 |

## 六、这一轮结束时该是什么样

1. `schema/` 里三份派生物都反映真实形态，且守卫比对三份；
2. 登记表是**唯一**的特效真相，且带 `space`（可校验，不靠注释）；
3. **加一个特效 = 一个登记项 + 一个 pipeline**，不用动渲染主路径；
4. 有一条守卫盯着"登记了没实现"和"实现了没登记"；
5. 转场去枚举化**有明确结论**：做了（带迁移与逐字节判据），或写明不做及理由——
   **不悬空**。
