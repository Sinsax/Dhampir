# 网页动画对齐与 HTML 预览宿主 —— 计划

> **本文件是计划，不是承诺。** 承诺边界见 [docs/api.md](../docs/api.md) 的"承诺等级"那张表。
> **目的**：让"网页里写的动画"能被底座读成工程数据，并让 **HTML 预览 / wasm 预览 / native 导出**
> 三端的效果一致。

**上游决策（本文件的前提）**

1. 作者层从 **WAAPI / CSS** 起步 —— 它的产出**本来就是数据**（`getKeyframes()` + `getTiming()`），转译成本最低，
   而且浏览器本身就是现成的 oracle。
2. **GSAP 作为后续扩展**（同一个 `anim2doc` 接口加一个反射器），理由是上限与生态高、且可离线精确 seek。
3. **Lottie 不归作者层**，归"素材格式 / 上限地图"——它自带渲染语义，用之前得先有矢量原语。
4. **Remotion 一条路排除**（代码即视频：不可静态校验、导出必须烧浏览器）。

---

## 0. 一句话

**底座只做"数据与语义"，画面只由 dhampir 渲染；HTML 在前期作为"第二个宿主"加速设计完整度，
后期降级为面板与调试视图。** 一致性靠"同一份求值 + 同一个坐标系 + 共享预栅格化"维持，
差异写进**能力登记表**与**容差表**，而不是拿去比像素。

---

## 1. 目标与非目标

### 1.1 目标

| # | 目标 | 判据 |
|---|---|---|
| G1 | 一份网页动画 → dhampir 工程文件 | `dhampir probe` 绿 + `dhampir frame` 出图 |
| G2 | 同一份工程在 wasm 预览与 native 导出上**像素可比**（容差内） | 一条走过**真实预览链路**的判定 |
| G3 | HTML 预览与 dhampir 的**属性数值逐帧一致** | 逐帧数值比对，容差 1e-6 |
| G4 | 前期的设计完整度可以用 HTML 快速长 | 能力登记表随设计同步更新 |
| G5 | 后期可把预览整体切到 dhampir | 切换是"换渲染器"，工程文件一个字节不改 |

### 1.2 非目标（明确不做，免得范围膨胀）

- ❌ **不做编辑器 UI 产品化**（那是下游；本仓只出"能力边界表 + 缺口表"）。
- ❌ **不做版式/布局**（WAAPI 只驱动属性，不排版；布局是另一个课题）。
- ❌ **不接受代码**（`onUpdate` 里的任意 JS 一律不转译）——铁律"特效是类型 + 参数的声明式数据"。
- ❌ **不碰运行时交互**（滚动、指针、焦点、`backdrop-filter` 之外的浏览器合成语义）。
- ❌ **不补缓动全集**（第一版只支持 WAAPI 能产出的那几种）。
- ❌ **不动渲染管线**（读回型、几何/矢量型是后续课题，见 §5 阶段 3/4）。

## 2. 前提：三端一致其实是两个不同的问题

| 对比 | 是不是同一个渲染器 | 能做到什么 |
|---|---|---|
| **wasm ↔ native** | **是**（同一份 core + 同一份 WGSL，只是宿主不同） | **像素级可比**（配容差表） |
| **HTML ↔ wasm / native** | **不是**（浏览器 CSS 合成器 vs WebGPU 管线） | 只有**数值级一致**，像素不承诺 |

**判据**：先问这两端跑的是不是同一份求值。是 → 谈像素；不是 → 只能谈数据。

---

## 3. 三角约束与选定方案

"像素一致""HTML(CSS) 渲染预览""native 快速导出"三者构成一个三角，**只能取两样**：

| 组合 | 一致 | HTML 渲染预览 | native 导出 | 结果 |
|---|---|---|---|---|
| A | ✅ | ✅ | ❌（导出也得是浏览器引擎） | 就是 Remotion 那条路 —— 已排除 |
| **B** | ✅ | ❌（预览也走 dhampir 渲染） | ✅ | **选定** |
| C | ❌ | ✅ | ✅ | 不满足"逐像素"要求 |

**选定 B**：预览也走 dhampir 渲染（页面里就是一块 WebGPU canvas）。
"HTML 的快捷"由**外壳**保留：面板、时间线、交互、CSS 动画的壳仍然是 HTML；
**HTML 不负责画帧**，所以它不参与一致性讨论。

---

## 4. 三端口径表

| 对比 | 必须一致 | 机制 | 判据 |
|---|---|---|---|
| **wasm ↔ native** | 帧号 / 结构 / 成片形状 / 像素（容差内） | 一份 core + 一份 WGSL + **两端同一坐标系** | `check-dual-end` + SSIM 容差表 + `check-preview-parity` |
| **HTML 宿主 ↔ dhampir** | **属性数值**（每帧 x/y/scale/rotation/opacity + 特效参数） | HTML 宿主读同一份工程文件（它是第二个宿主） | 逐帧数值比对，容差 1e-6 |
| **HTML 宿主 ↔ native** | 同上 | 同上 | 同上 |

> **注意**：`check-dual-end` 的浏览器腿走的是**离屏合成**（`web/synthetic.html` → `render_png`），
> **完全不经过 `dhampir_project_draw`** —— 所以它那个 `1.000000` **证明不了预览这条链**
> （[docs/preview-cache.md](../docs/preview-cache.md) §4 已写明）。G2 的前置就是补这条判定。

## 5. 分阶段计划

| 阶段 | 做什么 | 出口（可判定） | 体量 |
|---|---|---|---|
| **0** | **口径与决策**（不写代码）：秒→整数帧的取整口径；缓动的契约形状；`iterations/direction/fill` 先展平。**已拍，见 [plan/web-animation-criteria.md](./web-animation-criteria.md)** | 口径文档 + 两条判据（老工程逐字节不变、已有关键帧用例一字不改继续绿） | 小 |
| **1** | **引擎侧唯一必动的代码**：加 `cubic-bezier(a,b,c,d)` / `steps(n)` / `linear(...)` | 每条缓动取若干控制点与浏览器 `Easing` 逐值比对（1e-6），两端调同一个函数 | 小 |
| **2** | **`anim2doc` 转译器**：动画快照 → 工程 JSON。第一版只覆盖 `transform(x/y/scale/rotation)` + `opacity` + 逐键缓动 | `dhampir probe` 绿 + `dhampir frame` 出图 | 中 |
| **3** | **HTML 宿主**（第二个宿主）：把工程渲染成 DOM/CSS，实现与 wasm 宿主同一套接口 | 同一份工程，HTML 侧能看到画面；与 wasm 逐帧数值一致（1e-6） | 中 |
| **4** | **设计完整度快速期**：只在 HTML 侧长（布局、文字、滤镜、遮罩），同步维护**能力登记表** | 登记表无未分类项；预览上角标能显示"dhampir 侧：✅ / ⚠️近似 / ❌未支持" | 中 |
| **5** | **能力逐条迁移**：先读回型（混合/发光/投影），再几何/矢量型（遮罩/裁剪）；每迁一条加一条判据 | 每条能力：HTML vs dhampir 差异 ≤ 容差；迁移过程本身就是回归 | 大 |
| **6** | **切换预览到 dhampir**；HTML 降级为面板 + 调试视图 | 走过真实预览链路的逐像素判定开始生效 | 中 |

**顺序不能换的原因**：阶段 3 之前没有"第二个宿主"就没有对照物；阶段 5 之前迁移没有判据；
阶段 6 之前没有走 `draw` 的判定，切过去也无法证明。

## 6. 三条纪律

1. **数据唯一**：HTML 宿主**也吃同一份工程文件**。它不许自己发明数据结构——每层一个绝对定位 div，
   `transform`/`opacity` 直接吃工程里的值，特效先用 CSS filter **近似**并在表里标注。
2. **债务可见**：维护 §8 的能力登记表，并在 HTML 预览上**打角标**（✅ / ⚠️近似 / ❌未支持）。
   凡是没登记的 CSS 用法，一律视为"切不过去"。
3. **宿主可换**：HTML 宿主与 wasm 宿主**同接口**。切换 = 换渲染器，不是换代码库。

## 7. 逐像素对齐清单（8 条）

要真正逼近 MAE 0 / ≤1 LSB，逐条对齐：

| # | 项 | 现状 |
|---|---|---|
| 1 | **单一求值**（`compose::evaluate` / `TimelineRenderer::render_frame` 只在 core） | ✅ 已有 |
| 2 | **同一份 WGSL**（两端读同一份文本，只按 WebGPU 能力下限写） | ✅ 已有 |
| 3 | **纹理格式与色彩空间一致** | ⚠️ **已知不一致源**：浏览器画布优先 sRGB，离屏是 `Rgba8Unorm` 线性 |
| 4 | **预乘 alpha + 同一套混合方程**（同一色彩空间里做） | 要写进口径 |
| 5 | **采样器** filter / address 对齐，**尽量避免非整数缩放** | 要写进口径 |
| 6 | **AA / MSAA 相同或两端都关** | 要写进口径 |
| 7 | **共享预栅格化**：文字/矢量/复杂静态元素 → 算一次、两端用同一份位图 | ✅ 缝已存在（`set_text_bitmap` / `set_bitmap` / `set_danmaku_bitmap`） |
| 8 | **判据走真实预览链路**（`draw → canvas → readback` vs `dhampir render` 输出） | ❌ **未做，是 G2 的前置** |

## 8. 能力登记表

**真值在 [web/capabilities.json](../web/capabilities.json)**，判据在 [scripts/check-capabilities.mjs](../scripts/check-capabilities.mjs)。
本文件**不再抄一份** —— 抄了就会漂，而这份仓库里所有会漂的抄本最后都变成了假数。

状态四种（图例也写在 JSON 里）：

| status | 含义 |
|---|---|
| `supported` | 底座已经画得出来，**而且有判据钉着** |
| `partial` | 有，但有限制或还没对账（限制写在 note 里） |
| `needs-primitive` | 底座还没有对应原语 —— 要做就得先加原语（读回型 / 几何矢量型） |
| `explicitly-not-doing` | 明确不做，理由写在 note 里 |

归属阶段：`have` / `2` / `3` / `5` / `other`（`5` = 阶段 5 的能力逐条迁移）。

判据钉六条：① 字段齐、状态与阶段都在图例里；② **`supported` 必须给出底座原语与判据证据**
（说支持就得有依据）；③ 证据里的每个路径**必须真的存在**；④ **DOM 宿主源码里出现的受管 CSS 能力必须登记**
（用了没登记 = 看不见的债）；⑤ 说明不许是占位符；⑥ id 唯一。

**数字不写在这里**（写了就是会漂的抄本）。要看就跑：

```bash
node scripts/check-capabilities.mjs            # 判据 + 当前分布
node scripts/check-capabilities.mjs --self-test # 8 个变异，证明它会红
```

改登记表的规矩：**改状态就要改证据**。`supported` 那条要是没有判据兜着，判据会直接判红 ——
这正是这张表与「我们大概支持吧」的区别。
## 9. 判定与验收

沿用本仓既有纪律：

1. **老工程逐字节不变**——每加一个概念都要过这一条（容器、缓动、宿主都适用）。
2. **每条判据配一条守卫，且守卫必须会红**（反向验证：临时植入违例确认它真会红）。
   **守卫若不会红，就不是守卫。**
3. **容差表单独成文件、可被引用**（铁律 5）。两份，各管各的：
   - `scripts/framediff-thresholds.toml`（+ `-exact`）：**引擎 vs 引擎**两条腿，差异性质是**舍入**，按实测最差值定档；
   - `scripts/dom-parity-differences.toml`：**引擎 vs 浏览器（DOM 宿主）**，差异性质是**算法不同** ——
     它按「允许的差异」记台账，state 三档（未实测 / 已实测 / 明确接受），
     判据 `scripts/check-dom-differences.mjs` 钉住「**没量过的不许写成数**」与「每条都要被引用」。
4. **不承诺的差异也要成文**：DROP 清单 + 能力登记表就是"允许的差异"。
5. **证据归档**：原始输出落 `records/` 与 `plan/*-evidence.md`。
6. **禁止在空文件集上通过**：没有文件可查时退出码是 2，不是 0。

## 10. 明确不做

- 布局 / 版式（另立课题）
- 运行时交互（滚动 / 指针 / 焦点）
- DOM 特有语义（`autoAlpha`、`display`、伪元素、媒体查询、选择器、层叠、继承）
- 任意 JS 副作用（`onUpdate` 之类）
- 插件生态（ScrollTrigger / Draggable / Flip / Observer / DrawSVG / MorphSVG / SplitText）
- 矢量渲染器（Lottie / Rive 那一路，属于"上限地图"的后续课题）

## 12. 参考项目与分工

| 项目 | 许可 | 用作什么 | 为什么 |
|---|---|---|---|
| **WAAPI / CSS Animations** | 标准 | **作者层起步** | 产出即数据（`getKeyframes()` + `getTiming()`），浏览器就是 oracle |
| **Theatre.js**（12.6k★） | Apache-2.0 | 可选：要"可视化作者"时替换手写动画 | `project.state` 就是 JSON；`studio` 是可摘的包 |
| **GSAP** | 以官网许可为准 | 后续扩展（同一 `anim2doc` 接口加反射器） | 上限/生态高、可离线精确 seek，是最好的 oracle |
| **FreeCut** | MIT | **上限地图**（功能清单 = 路线图） | 功能极全；但它**自带 composition runtime**，不要 fork |
| **OpenCut classic** | MIT | UI 范式 / 快捷键 / 时间线交互的**抄写对象** | 与 dhampir 同架构（Rust core + 两宿主）；不要用其重写版 |
| **Lottie** | 格式 | **素材格式**，不是作者层 | 自带渲染语义，用之前要先有矢量原语 |

**反对项**：任何 Remotion 内核的项目（代码即视频）；任何自带渲染引擎却不打算拆掉的编辑器。
