# 字形回退（glyph fallback）链的证据台账

这份文档收 T1–T4 那条链的**实测数字**。规矩与仓库里别的证据文档一样：
每一条判据都要能**复算**（命令、版本、期望值都写下来），并且每条判据都要有
**反向用例**——一个不能变红的判据不是判据。

本机环境（下面所有数字都出自这一套）：

| 项 | 值 |
|---|---|
| ffmpeg | `9.0.1-full_build-www.gyan.dev`（gcc 16.1.0 / MSYS2） |
| libass | 在（`--enable-libass`，`subtitles` 与 `ass` 滤镜都在） |
| `fc-list` | **没有** |
| fontconfig 默认配置 | **没有**（`Cannot load default config file`） |
| 系统字体 | `C:/Windows/Fonts/msyh.ttc`、`C:/Windows/Fonts/NotoSansSC-VF.ttf` |
| 非 ASCII 名字体 | `%LOCALAPPDATA%/Microsoft/Windows/Fonts/乐米波波体（免费商用）_爱给网_aigei_com.ttf` |

## T1：非 ASCII 字体路径不再静默失败

### 缺陷（先复现，再修）

同一份字体、同一行文字、同一个字号，只改**路径的写法**：

```bash
printf '笑靥如花' > t.txt
FONT='.../乐米波波体（免费商用）_爱给网_aigei_com.ttf'

# A：原始非 ASCII 路径
ffmpeg -v error -nostdin -f lavfi -i "color=c=black@0.0:s=400x60,format=rgba" \
  -vf "drawtext=fontfile='${FONT}':textfile='t.txt':fontsize=40:fontcolor=white:\
expansion=none:x=(w-text_w)/2:y=(h-text_h)/2" \
  -frames:v 1 -f rawvideo -pix_fmt rgba - > a.raw 2> a.err

# B：同一份字体复制成 ASCII 名
cp "$FONT" lemi_ascii.ttf   # 然后把上面那句的 fontfile 换成 lemi_ascii.ttf
```

| | A（原始非 ASCII） | B（ASCII 拷贝） |
|---|---|---|
| 退出码 | **139**（SIGSEGV） | 0 |
| 产出字节 | **0** | **96000** = 400×60×4 |
| 非零 alpha 像素 | 0 | **3184** |
| stderr | `Fontconfig error: Cannot load default config file: File not found` | 空（0 字节） |

A 连跑 3 次：`139 / 139 / 139`，每次都 0 字节——**稳定复现**。

### 为什么这条最坏：它连"退出码非零"都不一定给

上表里 A 是**段错误**（139），所以 `run_ffmpeg` 里"退出码不是 0 就报错"那条**接得住**它。

但同一份探针在别的形态下给的是 `rc=0 && 0 字节`（任务书里记的那一版）——
**真正接住这一个缺陷的是"产出字节数不对就报错"那一条**，不是退出码那一条。
本仓在这条路上的安全性**建立在字节数检查上**，所以下面专门有一条反向用例盯着它。

### 修法

`crates/dhampir-worker/src/text_raster.rs`：路径含非 ASCII 字节时，把字体**复制**到
一份 ASCII 名的临时路径再用（`ascii_font_path` / `stage_font_file`），用完由
`StagedFont` 的 `Drop` 删掉。

* 临时名 = `dhampir-font-{pid}-{内容 FNV-1a}{扩展名}`：内容进名字，
  于是"换一份字体"与"同一份字体"在参数串上可区分，且残留文件可识别。
* 用 **copy 不用 hard_link**：Windows 上跨卷硬链会失败，而临时目录与字体目录常常不同卷。
  一份中文字体约 2.5 MB，搬一次的代价远小于一次 ffmpeg 进程。

### 验收数据

**1）老工程逐字节不变（T1 的硬前提）**

```bash
dhampir frame --project fixtures/sample-project.doc.json --frame 15 --out <dir>
```

| | sha256 |
|---|---|
| 改动前（HEAD = 97c3d8e） | `91ac70187a5d3fdd7d01a568effa7f7df7463783c0623b583bd6a8aeca3ceff2` |
| T1 改动后 | `91ac70187a5d3fdd7d01a568effa7f7df7463783c0623b583bd6a8aeca3ceff2` |

**逐字节相同**。判据 `不画阴影时参数串逐字符与改动前相同`（`frozen_argv`）继续绿。

**2）非 ASCII 路径真的画得出来（端到端）**

```bash
dhampir frame --project fixtures/sample-subtitle.doc.json --frame 15 \
  --out <dir> --font-file '...\乐米波波体（免费商用）_爱给网_aigei_com.ttf'
```

* `failed: false`、`lines_failed: 0`、`lines_drawn: 1`、`cache_misses: 3`
* 出图 sha256 `6712558a430a93cecde4cc92bd7007f6d09e792404aba096f7b918076b3062a3`
* 目视：笔画正常，无 .notdef 方框
* 对照（同一帧换 ASCII 名体的 `msyh`）：`failed: false, lines_failed: 0`，
  sha256 `cbf4754cc8d2aaf83cb4ad6401a39922385230f0c219bc16e5eeafe0dba0c91a`
  —— 两份**不同**是对的：不同的字体本来就该画出不同的像素。
  这条只证"两条路都能跑通"，不证"像素一致"。

**3）临时文件清干净**

跑完上面那条端到端之后，`$TEMP/dhampir-font-*` 计数 = **0**。

### 反向用例（会红的那一半）

| 变异 | 预期红的那条判据 | 实测 |
|---|---|---|
| 让 ASCII 路径也走复制（`is_ascii() && false`） | `ascii_字体路径不搬_这一条是默认路径字节冻结` | **红**（29 过 / 1 挂） |
| 默认滤镜串里多塞一个字符（`fixbounds=none`） | `不画阴影时参数串逐字符与改动前相同` | **红**（29 过 / 1 挂） |
| 源文件不存在 | `搬字体失败要响亮报错而不是递一个空路径` | **绿**（在修好的实现上） |

两个变异各自**只**挂掉那一条判据，没有连带红——说明判据是**对着**那件事的。

**一条要如实记下的边界**：变异"搬了却仍用 `key.font_file`"（把搬出来的路径丢掉）
**不被任何断言接住** —— 它只是编译出一个 `unused variable: font` 警告。第一版实现里
这是个真的静默错法。改法不是补一条判据（那要注入一个钩子），而是**让它写不出来**：
`ascii_font_path` 返回 `StagedFont`，路径只从 `StagedFont::path()` 出，
调用方**没有第二条路径可选**。这条纪律记在这里，将来重构这一段时别退回去。

### 一条环境限制（不是产品缺陷）

DSH 的文件沙箱会让**位于工作区内的可执行文件写不了 `%TEMP%`**
（`拒绝访问 (os error 5)`）。`cargo test` 的产物在 `crates/*/target/` 里，正好撞上，
所以两条**造源文件 / 看临时目录**的单测在这个环境里拿不到草稿目录。

处理办法是 `writable_scratch_dir()`：**真去试着建一次**，建不了就打印原因并如实跳过
（返回 `None`），而不是让一条环境差异伪装成"实现坏了"。

**这条限制吃掉的是测试的覆盖，不是产品的行为**——产品路径在**同一台机器**上验过：
把 `dhampir.exe` 拷到工作区外再跑，非 ASCII 字体路径端到端出图成功（见上"验收数据 2"）。
在不受沙箱约束的环境里，那两条单测会真正执行。

## T2：走 libass（`subtitles=`），缺字由逐字形回退补上

### 立意

`drawtext` **不做逐字形回退**：字体里没有那个字形就画 `.notdef`（空心方框），
**退出码 0、不报警、`lines_failed` 还是 0**。libass 做。

代价是**破坏性**的：这一版之后，**每一个老工程的字幕像素都会变**（渲染器换了）。
没有任何开关能回到老样子 —— 老的那条路正是这一条要修的病。

### 验收数据 1：缺字真的被回退补上了

同一份字体（`乐米波波体…aigei_com.ttf`，**没有** U+9765 靥）、同一串「笑靥如花」、
同一张 400×120 画布：

| 路径 | 结果 |
|---|---|
| `drawtext`（T2 之前） | 靥 画成 **`.notdef` 空心方框**；退出码 0、不报警 |
| `subtitles=` + `fontsdir=`（T2 之后） | 靥 由回退字体画出；`fontselect` 出现**第二行** |

`fontselect` 的原文（`-v info`）——**第二行就是回退发生的硬证据**：

```text
fontselect: (乐米波波体, 400, 0) -> LemiBoBoTi-Regular, 0, LemiBoBoTi-Regular
fontselect: (乐米波波体, 400, 0) -> MicrosoftYaHeiUI, 1, MicrosoftYaHeiUI   ← 靥 回退
```

端到端（真 CLI，`--font-family` 由工程契约给）：

```text
dhampir.exe frame --project target/t2verify/gf-family.doc.json --frame 0   --out … --font-file "<乐米…ttf>" --font-dir "<那份字体所在目录>"
→ failed: false, lines_drawn: 1, lines_failed: 0
```

像素上肉眼可核：`target/t2verify/on-dark.png` 里「笑靥如花」四个字都在，
笑/如/花 是圆体的乐米、**靥 换了一副（明朝体）字形** —— 一眼看得出是回退来的，
而不是方框、也不是"四个字全被换掉"。

### 验收数据 2：家族名从契约来，不推

libass **按家族名找字体，不认文件路径**。而**从文件名推出来的名字它认不出来**：

| 传给 libass 的 `FontName` | `fontselect` 解析结果 |
|---|---|
| `乐米波波体（免费商用）_爱给网_aigei_com`（文件名主干） | **ArialMT**（无 CJK 字形） |
| `staged`（换个文件名） | **ArialMT** |
| `LemiBoBoTi`（英文内部名） | **ArialMT** |
| **`乐米波波体`（真家族名）** | **LemiBoBoTi-Regular** ✓ |

**用错名字的后果是静默用错字体**：`lines_failed: 0`、`issues: []`，只是字全变了
（ArialMT 或某个系统回退）—— 比 `.notdef` 方框更难查，因为方框至少看得出来。

所以家族名走**既有契约** `SubtitleStyle::font_family`（`layer.rs:524`，
已经流到 `core/overlay.rs:363`），`--font-file` 退居兜底。**没有新加概念、没有解析字体文件**
（"本仓不解析字体文件"那条约定没破）。

**功能已验证**：同一份 fixture，只改工程里的 `font_family`：

| 工程里的 `font_family` | 帧 sha256 |
|---|---|
| `乐米波波体` | `4e55e52fd9b5a40e…` |
| `msyh` | `b17a231cec5d5cf3…` |

两者**不同** ⇒ 名字真的在选字体，不是一个被忽略的字段。

### 验收数据 3：字号必须按 libass 的虚拟画布高补偿（T2 最阴的一步）

libass 把 SRT 画在默认 **384×288** 的虚拟画布上再缩放；`subtitles=` 喂 SRT 时
**没地方指定** PlayRes（`original_size=` 实测**不管用**）。于是 `force_style` 的
`FontSize` 是**虚拟画布尺度**上的行高，真实字号 = `FontSize × (真实高 / 288)`。

`FontSize = font_px × 1.25 × (288 / 位图高)`，两个系数都量过：

| 画布高 | 目标 font_px | 算出的 FontSize | 实测墨迹高 | 老 `drawtext` 的墨迹高 |
|---|---|---|---|---|
| 90 | 40 | 160 | 40 px | 39 px |
| 90 | 60 | 240 | 58 px | 58 px |
| 200 | 40 | 72 | 39 px | 39 px |
| 200 | 60 | 108 | 58 px | 58 px |
| 360 | 40 | 40 | 39 px | 39 px |
| 360 | 60 | 60 | 58 px | 58 px |

**画布高正好 288 时补偿因子为 1** —— 所以这个坑只在别的画布高上现形
（第一批真机测试就是栽在这里：补偿前只有 323 个覆盖像素，
看着像"字体没装上"，其实是字体被缩到了 0.69 倍）。

### 反向证据：判据坏了会红

每条判据都拿一个**真变异**验过它会红：

| 变异 | 变红的判据 |
|---|---|
| `font_family` 不生效，永远退回文件名主干 | `家族名优先用契约给的_没给才退回文件名`、`真机_缺字走逐字形回退而不是_notdef` |
| `fontsdir=` 写死，不跟键走 | `字体目录进参数串且跟着键走`、`不画阴影时参数串逐字符与冻结串相同` |
| 字体目录定不下来时静默放行 | `字体目录定不下来要响亮报错` |
| 去掉 PlayRes 补偿 | `字号要按_libass_虚拟画布高补偿`、`不画阴影时参数串逐字符与冻结串相同` |

### 这一版**收窄**了两处口径（如实记，不要当成 bug）

1. **填充与描边共用一张覆盖掩码**，所以 `OutlineColour` 被迫也是白墨 ——
   **描边的颜色在这一步不能来自 `stroke_color`**。理由：libass 输出到 `format=rgba`
   时 **alpha 恒为 0**、颜色是**已合成**的；黑描边像素 `(0,0,0,0)` 与"完全透明的背景"
   **逐字节相同**（实测一张 640×90 的图里 56806 个 `(0,0,0,0)`），覆盖度**数学上恢复不出来**。
   填充与描边都画白墨，覆盖度才回得来，颜色交回 `tint`（这本就是本模块的既有契约）。
   峰值是 **255 不是 235** —— 235 是"白填充与黑描边在同一像素混色"的中间值，不是上限。
   **T3 要处理描边那一圈的覆盖度语义。**
2. **回退落到哪个字体依赖机器上装了什么**（实测 → `MicrosoftYaHeiUI`）。
   同一台机器上的两次出片一致（目录是给定的），**跨机/跨平台可能不同**。
   回退字体集合该由谁提供见 T4。

### 顺带纠正任务书里的两处

* 「非 ASCII 字体路径 rc=0」—— **实际是退出码 139（SIGSEGV）、0 字节**
  （见 T1 那一节，`$?` 当时是在 `| head` 之后取的）。
* 「要随行生成一份 `fonts.conf` 走 `FONTCONFIG_FILE`」—— **实测不必**。
  ffmpeg 的 `subtitles`/`ass` 自己有 `fontsdir=`：`env -u FONTCONFIG_FILE` 下
  rc=0、`fontselect` 两行都在、没有 `Cannot load default config file`。
  少一个会腐烂的外部文件。

## T3：覆盖度口径对齐（RGB→alpha）+ 边缘判据

### 要解决的问题

libass 输出到 `format=rgba` 时 **alpha 恒为 0**，覆盖度在 **RGB**；而底座
（`tint` 那条路）读的是**预乘的 alpha**。直接把 libass 的字节当位图用 ⇒
`tint` 拿 `alpha=0` ⇒ 把 rgb 清成 0 ⇒ **一张全透明的位图**，
而它的尺寸、字节数、ffmpeg 退出码**全都是对的**。那是这条链上最坏的一种失败：
**一行看不见的字**。

搬运由 `coverage_from_libass` 做（`coverage = mean(r,g,b)`），
峰值实测 **255**（不是 235 —— 235 是"白填充与黑描边混色"的中间值，见 T2）。

### 判据一：逐字形比边缘**斜坡宽度**（主判据）

**为什么不逐点比**：两条路的**每字推进宽度**差 1%。用「口」重复 n 次实测：

| 字数 | 老路宽 | 新路宽 |
|---|---|---|
| 1 | 32 px | 32 px |
| 2 | 72 px | 71 px |
| 3 | 112 px | 110 px |
| 5 | 192 px | 190 px |

即**每字累计偏 0.4 px**。这是字距/取整差异，不是渲染错。但逐点比会把它
**放大**：边缘横挪 1 px = "0 对 128"。累积到第 5 个字已错 2 px，于是：

| 比法 | 最大差 | 中位差 | 结果 |
|---|---|---|---|
| **整串**「口日目回田」逐点比 | 247 | 76 | 45.8% 落在容差内 —— **看着像两条路差得远** |
| **单字**「口」逐点比 | 143 | 40 | 96.9% 落在 128 内 |

所以判据**按单个字形**立（字距属于排版，不属于覆盖度），
且**主判据判结构不判逐点值**：逐点差的主要来源是"斜坡相位差半个像素"
（老 `…140, 255, 255, 208, 0…` vs 新 `…108, 255, 255, 226, 0…`，
两次跨越**都在 2 px 内从 0 走到 255**）。

**主判据 = 边缘斜坡宽度**（`ramp_width`）：

| 字 | 老路 `drawtext` | 新路 libass |
|---|---|---|
| 口 | 0.63 px | **1.65 px** |
| 日 | 1.43 px | **2.41 px** |
| 目 | 1.21 px | **3.17 px** |
| 田 | 1.10 px | **1.63 px** |

**四个字全部同向偏宽** —— 这是两条渲染器的**真实差异**（不同的轮廓扫描、
不同的抗锯齿核），不是搬运写错。它**不破坏**既有的"窄抗锯齿"口径
（1.6~3.2 px 仍在"窄"的范围里，模糊会是十几像素），但**是一次可见的观感变化**：
**新版字幕边缘比老板略柔**。这条与 T2 的"字幕像素会变"是同一件事的两面。

判据据此立成两条：① 两条路**各自**的斜坡宽度必须落在 `0.5..=3.5` px
（太宽=糊了，接近 0=硬边没抗锯齿）；② 新路**偏宽有界**（≤ 2.5 px，
实测最大 1.96，留余量）且**不许更窄**（更窄 = 边缘被二值化了）。
辅助判据用**中位差** ≤ 130（实测 20~77），抓"整条边整体偏移/整体变淡"。

### 判据二（核心反向用例）：不搬运必须被抓住

`真机_直接把_libass_的_alpha_当覆盖度会被抓住`：同一份原始字节 ——

* **不搬运**、按 alpha 读 ⇒ 包围盒必须 `None`、边缘像素必须为 **0**（全空）；
* **搬运之后** ⇒ 必须有墨、边缘像素 > 30；
* 并断言原始的 alpha **恒为 0**（`raw_ink == 0`）。

### 判据三：描边颜色的已知边界被钉住

契约里的 `stroke_color` **这一步消费不了**（填充与描边共用一张掩码 ⇒
描边也必须白墨 ⇒ 颜色交回 `tint`）。这条**已知边界**由
`描边颜色当前不受_stroke_color_控制_这条边界钉住` 显式钉住：
换 `stroke_color` **参数串必须逐字符相同**，且描边必须是白墨。
将来若拿到分层掩码，这条会红 —— 它会提醒实现者去更新文档与 `tint` 口径。

### 反向证据：判据坏了会红

| 变异 | 变红的判据 |
|---|---|
| **删掉覆盖度搬运**（直接用 libass 字节） | **4 条**，含边缘判据与缺字回退那条 |
| **覆盖度二值化**（>0 就算 255，边缘硬化） | `真起_ffmpeg_画出一行中文字`、`真机_直接把_libass_的_alpha_当覆盖度会被抓住`、`真机_边缘覆盖度与老路同量级` |
| **把 `stroke_color` 塞回参数串** | `描边宽度与颜色都来自契约`、`描边开关决定有没有_outline项`、`不画阴影时参数串逐字符与冻结串相同` |

## T4：字体定位契约 + 跨仓边界

### 契约（接既有字段，不新建概念）

字体来源**两条**，按优先级取：

| 顺序 | 来源 | 说明 |
|---|---|---|
| 1 | **`--font-dir` + 工程里的 `font_family`** | 按**族名**在那个目录里找文件 |
| 2 | **`--font-file`** | 点名一份，兜底 |

`font_family` 是**契约里早就有的字段**（`SubtitleStyle::font_family` /
`DanmakuSpec::font_family`，`layer.rs:524`/`:774`），语义一直是
**"从你给我的目录里按这个名字找"**。libass 要的正是"名字 + 去哪找"，所以这是**接线**，
不是新建概念。**不生成 `fonts.conf`、不碰 `FONTCONFIG_FILE`** ——
`fontsdir=` 就够（`env -u FONTCONFIG_FILE` 下实测 rc=0、`fontselect` 两行都在）。

### 端到端验过：只给目录 == 点名一份字体

同一 fixture、同一帧，**不给 `--font-file`**、只给 `--font-dir`（目录里放乐米字体）：

```text
dhampir.exe frame --project …/gf-family.doc.json --frame 0   --out … --font-dir target/t4verify/dir        (工程里写 font_family: 乐米波波体)
→ failed: false, lines_drawn: 1, lines_failed: 0
```

| 走法 | 帧 sha256 |
|---|---|
| 只给 `--font-dir`（按名字找） | `4e55e52fd9b5a40ed5ac6cd5ce669a952e3b0b4faffb02564dc311249c44687d` |
| `--font-file` 点名同一份 | `4e55e52fd9b5a40ed5ac6cd5ce669a952e3b0b4faffb02564dc311249c44687d` |

**两者逐字节相同** —— 契约那条路真的接到了同一份字体上。

### 响亮失败：三条静默路都被堵上

| 情况 | 行为 |
|---|---|
| `--font-dir` 指不到目录 | **退出码 2**（哪怕有 `--font-file` 兜底） |
| `--font-dir` 存在但一个字体文件都没有、且没给 `--font-file` | **退出码 2** |
| 两条都没给、工程却有字幕 | 出片**判失败**，并**在出片前**就出声 |
| 工程点名 `font_family`，目录里没有那份 | 判失败（`subtitle_font_missing`），**消息点出是哪个名字、哪个目录** |

最后那条的消息原来只有一句「宿主没有给字体（--font-file）」——
**把"没给"与"给了目录但没有点名那份"混成一句**，用户会去查他**没写错**的那个参数。
现在由 `font_missing_reason` 分三种说法，各有判据。

### 一处缺口（真出现过，已修）

出片路径上那条"没给字体"的提前出声**曾经只看 `--font-file`** ——
于是"只给 `--font-dir`"（契约本就支持的用法）被误报成缺字体。
已改成"两条都没有"才出声。

### 回退：确定性边界（如实记，**未定项**）

缺字时 libass **逐字形回退**到另一份字体（这是 T2 的立意）。实测缺 U+9765 靥 那次：

```text
fontselect: (乐米波波体, 400, 0) -> LemiBoBoTi-Regular, 0, LemiBoBoTi-Regular
fontselect: (乐米波波体, 400, 0) -> MicrosoftYaHeiUI, 1, MicrosoftYaHeiUI   ← 系统字体
```

⇒ **回退落到哪一份取决于机器上装了什么**：

* 同一台机器、同一个 `--font-dir`，**两次出片一致**（目录给定，这条保得住）；
* 换机器/换平台，**缺字那几个字可能换一副字形** —— "两端可比"的已知边界；
* **回退用的字体集合该由谁提供：未与下游宿主（V-Trim）对齐，如实记为未定。**
  本仓没有字体栈，那是宿主/系统的事，这里不单方面假设。

这与既有的"两端比结构、不比字形"不冲突（wasm 侧走 canvas `fillText` +
系统字体，本就是**第三条独立路径**，见 `web/engine.js:20-30`）。

### 反向证据：判据坏了会红

**这里踩过一次坑，值得记。** 第一版的两条判据是**假的**：`resolve_font` 里有
**两条**能返回 `Err` 的路（目录不**存在** / 目录里**没有字体文件**），
而我只断言"返回了 Err" —— 于是把"存在性检查"整条删掉，它也照样红
（不存在目录反正也读不出字体文件，第二条路接住了）。**删掉真代码它不红。**

修法各有判据**互相隔离**：存在性那条**给上** `--font-file` 兜底
（第二条路不再触发）、空目录那条**拿掉**兜底。改完两条变异各自变红：

| 变异 | 变红的判据 |
|---|---|
| 删掉"目录不存在"检查（有兜底） | `字体目录不在要响亮报错` |
| 删掉"目录里没有字体文件"检查（无兜底） | `字体目录空且没兜底要响亮报错` |
| 原因解释退回通用说法（不点名字） | `缺字体的三种原因各有各的说法` |

同一个坑还咬到第二次：空目录那条判据原本**自己造临时目录**，
而本沙箱里"工作区内的可执行文件写不了 `%TEMP%`" ⇒ `create_dir_all` 失败
⇒ **静默跳过** ⇒ 变异不红。改成用一个**已存在、且确实没有字体文件**的目录
（crate 的 `src/`），并**自检前提**（那里真的没有字体文件）。

## 这一版对"手写数字"的处置（Lead 复核发现）

`best_alignment` 那张「每字推进宽度」表原来没写**量法**，于是不可复现 ——
复量后确认原表用的是**补偿后**的 `FontSize`（画布 400×74 时是 195），
而按 `FontSize=40`（不补偿）量出来是另一组数。已改成把**量法写进表下**，
并加了一列"不补偿"作对照，同时**明确写"这张表只是动机、不是判据"**
—— 守这件事的是"单字比 + 斜坡宽度"那两条判据本身。

复量数据（`msyh`、`font_px=40`、画布 400×74、「口」重复 n 次）：

| 字数 | 老路宽 | 新路宽（补偿后，FontSize=195） | 新路宽（FontSize=40，不补偿） |
|---|---|---|---|
| 1 | 32 | 32 | 26 |
| 2 | 72 | 71 | 57 |
| 3 | 112 | 110 | 88 |
| 5 | 192 | 190 | 152 |

在 1000×288 画布上复量，前两列一致。
