## 四、明确规避 / 划界（不是遗漏）

| 项 | 为什么不做 |
|---|---|
| 原生解码器 | dhampir-media 的 5 个 trait **零实现**，已加声明与守卫。解码归宿主：浏览器走 WebCodecs、服务端走自己的解码器 |
| 成片编码的 Rust 绑定 | 有意为之：用 FFmpeg CLI。不引绑定是刻意的取舍 |
| ping-pong 类混合模式 | 需要读目标像素，是另一个数量级的改动，单独立项 |
| 上传管线 / 对象存储 / 账号 | 属下游 |
| 任务队列持久化 | 本机后端计划用内存队列，**重启即失**，须写进文档 |
| 嵌套序列 / 预合成 / 实时协作 | 不在范围内 |
| 内部取证 JSON 纳入契约 | 纳入等于把内部工具变成承诺 |

## 六、一个流程缺陷与它的修法（记录在案）

**同类错误犯过三次**：在提交信息里声称了没核的东西。

| 提交 | 声称 | 实际 |
|---|---|---|
| ae84d37 | 手写 JSON 清零 | 还剩 3 处 |
| 2e2ef52 | 无警告 | 1 条 |
| 06af405 | 无警告 | 2 条 |

**根因是流程，不是疏忽**：验证与写提交信息放在**同一个程序**里，
于是消息永远在**看到结果之前**就写好了 —— 写下的永远是预期，不是实际。

**改法（已生效）**：两者分成两个程序。第一个只跑验证并打印数字，
第二个根据**已看到的**数字写消息。266b760 是第一次真正照此执行。
